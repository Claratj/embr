## Recommended execution order

**1 → 3 → 2 → 4**

- **001** is fully independent — it edits `VARIANT_CLASSES`/`STATE_CLASSES` on `Button.tsx`/`Tag.tsx`, disjoint from every other plan's edits (`BASE_CLASSES`, `FIELD_BASE_CLASSES`). Safe to run first, last, or in parallel with anything else here.
- **003 before 002**: plan 003 adds `active:scale-[0.97]` and a `transform` to `Button.tsx`'s `BASE_CLASSES`. Plan 002's Button step is written with a conditional (see its Boundaries section) that behaves differently depending on whether 003 has already landed — running 003 first means 002's executor takes the "Tag-style" branch (`motion-reduce:transition-[background-color]`) instead of "delete the guard entirely." Running 002 first is not wrong, just means Button temporarily has no `motion-reduce:` class at all until 003 re-adds one.
- **002 before 004** (or re-read the file either way): both plans edit `field-classes.ts`'s `FIELD_BASE_CLASSES` — 002 removes the trailing `motion-reduce:transition-none`, 004 changes `ease-out` to `ease-default` earlier in the same string. Neither depends on the other's content, but an executor should re-read the current file before editing rather than blindly pattern-matching the "Current" snippet in either plan, per each plan's own Boundaries note.
